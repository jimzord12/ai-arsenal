## Acceptance criteria

1. The work-item validator accepts `--work-item none` only when `NEXT.md`
   contains exactly one explicit `Active work item: none` field and exactly one
   explicit `Pipeline step: none` field; missing, partial, duplicate,
   malformed, or inconsistent registration is invalid structural state.
2. Disposable validator tests prove the missing-registration rejection and
   retain coverage for the explicit inactive state and conflicting
   registrations.
3. `scope-monorepo-change` owns contract revisions: it archives the replaced
   current contract, writes the incremented current contract, archives every
   invalidated downstream current artifact, and routes to plan creation.
4. `plan-monorepo-change` owns plan revisions: it archives the replaced
   current plan, writes the incremented current plan, archives every
   invalidated downstream current artifact, and routes to fresh approval.
5. Each archive preserves the artifact bytes except for changing the header
   status to `superseded`; current downstream artifacts are archived in reverse
   dependency order before removal, so no historical record is silently lost.
6. Contract and plan revisions preserve exact prerequisite revisions,
   invalidate approval, implementation, verification, and reconciliation as
   applicable, and require explicit approval of the revised plan before later
   implementation.
7. Focused validator and workflow checks, the full repository check, both
   workflow validators, and whitespace validation pass after the repairs.
