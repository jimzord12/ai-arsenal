## Decisions

- Repository discovery walks upward from the invocation working directory and selects the nearest ancestor whose `.git` exists as either a directory or worktree file. Reaching the filesystem root produces stable `SKILLS_REPOSITORY_NOT_FOUND` with no repository write.
- Package payload assets are byte-equal copies of the four canonical `SKILL.md` sources and the package-owned protocol. Installation rewrites exactly the one canonical monorepo-relative protocol link into `references/agent-workflow-protocol.md`; no lifecycle text changes.
- Each installed target contains `SKILL.md`, the local protocol reference, and `.jz-trello-flow-managed.json` identifying `jz-trello-flow`, replaceability, skill name, and marker version.
- Payload preparation occurs in an OS temporary directory. All four staged directories are complete before official `skills-ref validate` begins, and all four validations complete before target mutation. Missing `skills-ref` returns stable `SKILLS_VALIDATOR_UNAVAILABLE`; invalid content returns `SKILLS_PAYLOAD_INVALID`.
- The public runtime invokes `skills-ref` from `PATH`. Documentation pins the required executable to official `skills-ref@0.1.0` from `agentskills/agentskills@38a2ff82958afee88dadf4831509e6f7e9d8ef4e`; implementation and verification used that exact external checkout/environment.
- Dry-run performs discovery, preparation, and official validation, reports four `installed`/`replaced` actions, and writes nothing beneath the target repository.
- Real replacement first copies the already-validated stage into a same-filesystem transaction directory, then backs up and swaps only the four managed names. A later failure restores completed targets in reverse order; unrelated skills are never enumerated for removal or changed.
- `skills install` is routed before configuration loading and accepts only `--dry-run` and the existing common `--output`; it never receives Trello board, credential, version, or operation options.
- The packed acceptance test is conditional on `JZ_TRELLO_FLOW_TEST_SKILLS_REF` so ordinary environments without the external official tool do not pretend to validate it. The required implementation/verification run supplied the exact pinned executable and passed. Turbo's root test task did not propagate that custom test-only variable, so `pnpm check` passed with the packed suite skipped there; the same packed suite passed separately against the exact package snapshot immediately before and after the root gate.
- The explicitly generated ignored tarball remains at repository root for supervisor inspection: `jz-ai-arsenal-trello-work-cli-0.3.0.tgz`, 64,783 bytes, SHA-256 `f678afb30cfe48a663e25897f8c2084900129999be2fbe85298cc38d5d1fbf90`. It was not published or installed globally.
