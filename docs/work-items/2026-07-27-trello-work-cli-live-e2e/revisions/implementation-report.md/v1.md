## Decisions

- Board selection is stateless and explicit per board-dependent command. `TRELLO_BOARD_ID` is ignored; selectors resolve by readable 24-character ID or one exact readable name.
- Board and list reads expose only stable safe identity/state fields. Duplicate exact names fail with safe board identities and no mutation.
- List create/update/close are board-scoped, verify ownership before mutation, support dry-run and operation IDs, persist replay identity in list action/name history, detect collisions, and return credential-free ambiguous/partial recovery records instead of blind retries.
- List close represents Trello archive/close and rejects nonempty lists before mutation with only the blocking count.
- Existing Work Unit CLI routes now resolve the explicit board before loading board-dependent configuration; direct card/list resources are checked against that board.
- The live suite is a separate `test:live` command. Its offline preflight validates explicit opt-in, process-environment credential-source confirmation, exact allowlisted board ID, selector, six list IDs, transition graph, and reconciliation source before constructing or using a client. Normal tests skip the live scenario.
- Live cleanup is status-only for cards and closes only empty run-tagged lists; unresolved resources produce safe recovery records.
- Ambient `TRELLO_*` variables were stripped from every offline command. No live request was made because board/list identifiers were not confirmed.
