# Goal

Create a private TypeScript package, `@jz/ai-arsenal-trello-work-cli`, exposing the `work` executable and implementing the canonical offline Work Unit boundary: safe parsing, validation, deterministic rendering, authority-aware mutation planning, and a read-only `work create --dry-run --file <path> --output json` plan, ready for later Trello configuration and transport wiring.

## Non-goals

- Live Trello authentication, card creation, card updates, read-back, or reconciliation before board/list configuration is supplied.
- Bulk operations, AI planning, automatic Slice decomposition, GitHub synchronization, automatic estimation, deletion, checklists, or a transition state machine.
- Generic metadata update and live transition commands beyond the contracts needed to prevent unsafe future implementation.
- npm publication, package release, packing for distribution, global installation, commit, or push.
- Modifying either installed Hermes planning-skill package during this work item.

## Hard walls

- Package location: `packages/trello-work-cli` in the existing pnpm/Turborepo monorepo.
- Language: TypeScript.
- Package name: `@jz/ai-arsenal-trello-work-cli`; executable: `work`.
- The staged planner V1.1 fenced-YAML document is the canonical baseline: exactly one `# Work Unit`, one immediately following fenced `yaml` block, canonical metadata field order, and required sections in order.
- `parent` and `blocked_by` contain Work Unit IDs (`WU-N`), not Trello card IDs.
- Draft IDs and timestamps are null; persisted IDs are paired. `trello_card_id` is a 24-character hexadecimal Trello ID.
- `status`, IDs, and timestamps are system-managed and cannot be changed through a generic metadata patch.
- No Trello or other remote mutation may occur in this work item.
- Machine-readable output goes to stdout; diagnostics go to stderr; failures use stable codes and nonzero exit statuses.
- Work Unit IDs will use Trello's server-assigned, board-scoped sequential `idShort`: after card creation, `id = "WU-" + idShort`. This avoids a separate counter and relies on Trello's authoritative allocation under concurrent creation. Gaps from deleted cards are acceptable; IDs are never reused.
- Future live creation must create exactly one Inbox card with a unique operation identifier, derive `WU-N` from returned `idShort`, persist IDs/timestamps, read back, and avoid blind recreation after an ambiguous partial failure.
- Keep engineering depth production-pragmatic: supported offline happy paths, realistic validation and CLI failures, maintainable code, and essential gates without speculative infrastructure.

## Acceptance criteria

- The new workspace package participates in root formatting, linting, typechecking, and tests without adding a runtime dependency.
- A valid canonical pre-creation Work Unit Markdown file parses into typed metadata and ordered sections and renders deterministically without changing meaning.
- Invalid documents fail closed for malformed/unsafe YAML, unknown or duplicate fields, noncanonical field order, invalid enums/types/IDs/timestamps, duplicate relationship values, self-reference, mismatched ID pairing, forbidden legacy fields, missing/duplicate/out-of-order/empty sections, and invalid `Open Questions` usage.
- Draft validation requires `status: inbox`, null IDs, and null timestamps.
- The `work create --dry-run --file <path> --output json` command performs no remote mutation and emits a stable JSON plan containing validation outcome, current draft representation, intended Inbox creation/update/read-back operations, unresolved board/list configuration requirements, and the `idShort`-based ID strategy.
- Running `work create` without `--dry-run` while Trello configuration/transport is unavailable fails before mutation with a stable machine-readable error.
- CLI help and error behavior are tested at the real process boundary.
- The package documentation explains the skill/CLI boundary, canonical document contract, offline commands, `idShort` allocation design, deferred Trello configuration, and partial-failure rule.
